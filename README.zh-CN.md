# dsh-chat-screenshot

DeepSeek Harness插件：把一段对话渲染成一张PNG并写入剪贴板。

[English](README.md) | 中文

两个入口共用一条管线。输入框工具栏保留一个相机按钮，截取当前会话已加载的全部对话；每条已完成的回复在操作行里保留一个相机按钮，只截那一轮问答。浏览器拒绝写入剪贴板时，改为下载PNG。

## 入口

| 入口 | 位置 | 范围 |
| --- | --- | --- |
| 整段对话 | `conversation.input.right`，输入框工具栏右端 | 当前会话已加载的全部对话，先拉全历史 |
| 单轮问答 | `conversation.chat.assistant-actions`，该回复的操作行 | 从这一轮的用户提问开始，到下一个用户消息之前为止 |

两个按钮都只有图标：工作时显示转圈，成功时闪一次对钩，结果用按钮上方的提示条说明。

## 截图流程

1. 把已挂载的应用面克隆到一个隐藏舞台。舞台放在固定定位、零尺寸的容器里，页面的滚动几何不受影响，正在输入的输入框也不会被碰到。
2. 克隆里去掉对话之外的部件：输入框座位与用量胶囊、轮次导航栏、拖拽手柄、分页占位，以及每轮末尾的时钟与用量行。其中可选的那几项由设置决定，默认值与加入设置之前的画面一致。
3. 裁剪从第一轮开始到最后一轮结束，并在输入框统计条上方收口。上下各留同样的内边距，两条边的留白一致。
4. 克隆通过 `foreignObject` 放进一个以 data URL 加载的SVG文档，由浏览器自己完成栅格化，画面与屏幕一致。该文档无法解码时，退回手绘：读取浏览器给出的盒子与逐行文字矩形，画到 canvas 上。
5. 图片写入剪贴板。写入被拒绝或长时间挂起时，改为下载，文件名带会话与时间。

更早的历史由聊天视图自己的“加载更早”控件拉取。历史见底时该按钮不会消失：它留在布局里，变成禁用状态，可见标签换成“已到会话开头”，所以截图读可见标签，见到禁用即停。宿主确实拉不动时，截图照常进行，提示条说明图片只含已加载的轮次。

## 安装

```bash
dsh plugin --profile web add D:\Projects\Agent\DSH\Plugin\ChatScreenshot
```

移除：

```bash
dsh plugin --profile web remove dsh-chat-screenshot
```

插件名是`dsh-chat-screenshot`。安装后刷新页面。

## 使用

1. 打开任意会话。
2. 截整段：点输入框工具栏的相机按钮，等待“已复制长截图”提示。
3. 截单轮：鼠标悬停目标回复，点该轮操作行里的相机按钮，等待“已复制本轮截图”提示。
4. 到任意支持图片的地方按Ctrl+V粘贴。

复制成功时按钮图标短暂变为对钩。剪贴板不可用时改为下载PNG，按钮图标不变。

## 设置

设置里的ChatScreenshot一页分三组，改完立即对接下来的截图生效，不需要刷新。

| 分组 | 项目 |
| --- | --- |
| 隐藏的控件 | 时钟与用量行、思考与工具行、附件、轮次导航栏、拖拽手柄、回到底部 |
| 加入的内容 | 标题、副标题、页脚、轮次与日期行、与正文之间的分隔线 |
| 排布 | 对齐方式、外边距、缩放倍数 |

标题、副标题与页脚是纯文本，可以写`{turns}`、`{date}`、`{time}`。标题画在第一轮之上，页脚画在最后一轮之下，都在裁剪范围之内，因此和对话走同一条渲染路径。

这些选择存在当前浏览器的`localStorage`里，键名`chat-screenshot.options`。插件不注册Host侧配置，也不在服务端保存任何内容。存下的值不再对应某个选项时，落到最接近的选项；“恢复默认”回到加入设置之前的画面。

## 已知限制

- 图片只含对话本身：没有侧栏、没有输入框、没有其他会话。
- 内容超过画布预算（每边约16000px）时按比例缩小，提示条会说明缩放倍数。
- 只在悬停时出现的控件在图片里同样保持隐藏，因为克隆呈现的是实时状态，不会强制展开。
- 超过256px、或引用了外部符号的SVG图标不绘制，避免解码挂起。

## 目录结构

| 路径 | 作用 |
| --- | --- |
| `index.js` | Host半侧：没有要执行的逻辑，仅为满足加载器对插件条目的要求 |
| `src/client/apply.js` | 注册：语言表、样式表、两个入口、设置页 |
| `src/client/shell/` | 常量、React访问、保存的选项、文案表、样式表、状态与投递 |
| `src/client/dom/` | 克隆准备、历史分页、设置加入的内容块、轮次范围、截图本身 |
| `src/client/render/` | 渲染器选择、SVG文档、手绘、裁剪、画布预算 |
| `src/client/output/` | 剪贴板写入与下载 |
| `src/client/views/` | 按钮主体、两个入口、两个图标、设置页 |
| `src/client/manifest.json` | 打包顺序 |
| `client.js` | 生成的打包产物，不直接编辑 |
| `build.mjs` | 把各部分拼成`client.js` |
| `checks/` | 结构、语言、逻辑三项校验，另有一页验DOM行为 |

## 开发

```bash
node build.mjs            # 由 src/client 生成 client.js
node build.mjs --watch    # 改动即重新生成
npm run check             # 产物是否最新、结构、文案、逻辑
node checks/serve.mjs     # 再打开 http://127.0.0.1:8712/checks/dom.html 跑DOM校验
```

各部分都是node能单独导入的普通ESM模块，打包后合并到同一个函数作用域：顶层名称必须在整个包里唯一；某个部分用到了相邻部分的名称，仍要写`import`，因为合并后的作用域会掩盖漏写，而node下会直接报错。

所有面向用户的文案都在`src/client/shell/i18n.js`，并注册到客户端语言服务，切换语言时提示语无需刷新即跟着变。`checks/i18n.mjs`在以下情况下失败：某个键只有一种语言、占位符不一致、某个视图用了表里没有的键。

`client.js`在组合时确定内容版本，重新打包后运行中的宿主拿到的仍是旧字节。把插件关掉再打开，然后刷新页面。
